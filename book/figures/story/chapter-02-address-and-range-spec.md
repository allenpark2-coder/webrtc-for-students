## 目的

以同一張生活故事圖建立三個互相區分的直覺：

1. 只知道「大樓地址」仍不足以指定大樓內的服務，還要指出「辦公室服務入口」。
2. LAN 的「相對有限區域」與 WAN 的「通常較大地理範圍／更多獨立使用者」是相對尺度，不是以校園線、行政線或固定公尺數判定。
3. 在本章限定的 localhost HTTP 情境中，client／server 角色附著於一條 connection；換一條 connection，同一程式可能交換角色。

本圖只建立地址、入口、相對範圍與 connection-specific 角色的直覺，不把文件動線畫成真實資料路徑，也不解釋任何路徑選擇或後章機制。

## 讀者必須理解

- 「大樓地址」回答要到哪個概念位置；「辦公室服務入口」回答到達該位置後要找哪項服務。兩者必須是分開、缺一不可的標籤。
- 左側「相對有限區域」與右側「通常較大地理範圍／更多獨立使用者」只示範尺度差異。
- 校園、建築或行政邊界只屬故事場景，不能作 LAN／WAN 的正式分類公式；圖內必須直接寫出「無單一距離門檻」。
- client 與 server 不是貼在小明、小華或機器上的永久身分。角色只標在兩條 localhost HTTP connection 上；兩條 connection 的方向相反，讓同一程式在兩列交換角色。
- 文件圖示只是有邊界資料單位的生活直覺，不代表真實 packet、簽收、送達保證或實際道路。

## 元件

### 共用標題與圖例

- 圖頂標題：`地址、入口、相對範圍與 connection 角色`
- 全圖底部固定警語框：
  - `尺度示例，不是距離公式；校園線或行政線不能代替真實網路分類。`
  - `文件箭頭只表示故事中的交付方向，不表示真實資料路徑，也不保證送達。`
  - `client／server 只對應圖中的 localhost HTTP connection。`
- 三區使用明確編號與文字標題：
  - `A　地址＋服務入口`
  - `B　相對有限區域 vs. 通常較大範圍`
  - `C　角色附著於 connection`

### A：地址＋服務入口

- 固定角色小明，手持一份標示 `校務文件` 的簡化文件圖形。
- 一棟抽象行政大樓，外側有獨立標籤牌 `大樓地址`。
- 大樓內並列三個辦公室入口：`註冊組服務入口`、`出納組服務入口`、`設備組服務入口`。
- 小明的文件目的地只指向 `註冊組服務入口`；箭頭旁分兩段標示：`先找到地址`、`再找到服務入口`。
- 地址牌與入口牌使用不同形狀與不同層級位置；入口不可畫成機器上的洞，也不可使用 port number。

### B：相對有限區域與通常較大範圍

- 左側小框：`LAN：相對有限區域`。
  - 使用一棟建築的簡化外框，內有少量無個資的通用人物／位置符號。
  - 框線為實線，框下文字：`例如一棟建築內；仍須看具體網路設計`。
- 右側寬框：`WAN：通常較大地理範圍／更多獨立使用者`。
  - 使用兩至三個彼此分開的小區域圖形，以及多組通用人物符號，表達較大範圍與更多獨立使用者。
  - 框線為長虛線，框下文字：`可互連較小網路；WAN 不等於 Internet`。
- 兩框之間不放公里尺、比例尺、等號、行政界標或「跨過這條線就一定是 WAN」的箭頭。
- 兩框上方共同加一條文字括號：`相對尺度比較；無單一距離門檻`。

### C：localhost HTTP connection 角色交換小插格

- 外框標示：`同一台測試電腦上的兩個程式（localhost HTTP 情境）`，避免把 localhost 畫成跨裝置、跨 LAN 或跨 WAN 的路徑。
- 兩個固定程式框：左為 `程式 A（小明這次操作）`，右為 `程式 B（小華這次操作）`。程式名稱不包含 client 或 server。
- 第一列：
  - `connection ①` 箭頭由程式 B 指向程式 A。
  - 箭頭起點旁標 `這條 connection 的 client（建立）`。
  - 箭頭終點旁標 `這條 connection 的 server（接受）`。
- 第二列：
  - `connection ②` 箭頭由程式 A 指向程式 B。
  - 箭頭起點旁標 `這條 connection 的 client（建立）`。
  - 箭頭終點旁標 `這條 connection 的 server（接受）`。
- 兩列共用註記：`換一條 connection，同一程式可能交換角色；不泛化到所有通訊方式。`
- 角色文字只能附著於各列箭頭或箭頭端點的徽章，不得寫進人物、程式框或裝置名稱。

## 關係與方向

- 主要閱讀順序為 A → B → C；這是教學閱讀順序，不是資料處理流程。
- A 區只有一條由小明到註冊組入口的故事交付箭頭。箭頭經過 `大樓地址` 標籤，再終止於 `註冊組服務入口`，但不得畫成真實道路、網路線或保證到達的追蹤路線。
- B 區是左右並列比較，不畫成 LAN 自動「變成」WAN，也不畫跨過行政線的因果流程。
- C 區兩列 connection 使用相反方向，並各自標出建立／接受端。角色標籤必須隨箭頭反向而互換。
- A、B、C 之間不用共用箭頭；三區只是在一張圖中並列三個相互支援的概念。

## 非顏色辨識方式

- A、B、C 以區號、完整標題、位置與外框四重辨識，不只靠底色。
- `大樓地址` 使用直立地址牌；`服務入口` 使用門框加文字牌，兩者形狀與位置不同。
- LAN 例子使用實線框；WAN 例子使用長虛線框，兩者都直接寫完整名稱與尺度說明。
- C 區兩條 connection 以 `①`／`②`、上下位置與相反箭頭方向區分；每條箭頭都把 client／server 文字寫在相應端點。
- 通用使用者符號的數量只作輔助，`更多獨立使用者` 必須以文字明示。
- 警語使用帶標題 `圖例／邊界` 的實線資訊框；移除所有色彩後仍能完整理解。

## 對比要求

- 一般文字與背景對比至少 4.5:1；大型標題至少 3:1。
- 箭頭、外框、地址牌、入口形狀與背景對比至少 3:1。
- LAN 實線與 WAN 長虛線的線寬至少 2 pt；虛線間隔在縮至書頁欄寬後仍可辨識。
- 不把小字放在漸層、照片或複雜紋理上；標籤使用純色底或充分留白。
- 色彩只作次要分區提示，不承擔地址／入口、LAN／WAN 或 client／server 的唯一區別。
