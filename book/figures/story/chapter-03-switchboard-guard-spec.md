## 目的

用同一張生活故事圖建立兩組互相分離的直覺：

1. 「總機」只處理內外聯絡表示與暫時對照；「警衛」另依規則允許或阻擋。兩者不是同一工作，存在對照也不代表必然放行。
2. UDP 像一張張保留邊界的明信片，服務本身不保證送達或順序；TCP 像建立狀態後交付的連續紙帶，提供可靠按序的字流，但不保留應用表單邊界。兩者只比較 service semantics，不比較速度。

本圖是生活比喻腳手架，不是實際設備拓撲、封包擷取、產品 UI 或效能圖。總機與警衛可在同一設備、不同設備，或只存在其中之一；畫成兩站只為區分責任。

## 讀者必須理解

- 小明端的內側聯絡表示經總機後，可形成一筆有時間／實作邊界的暫時對照；這不表示所有 NAT 都會改 port，也不表示對照永久存在。
- 警衛的 policy 判斷獨立於總機的 mapping；`mapping 不等於放行`，`放行不等於 listener 存在`。
- 圖中外側看見的聯絡表示只是「外側觀察位址」。它不因位於畫面外側就自動成為 public IP address，也不是永久身分或可達保證。
- UDP 明信片保留每份資料的邊界，可用缺口與交換次序表示「可能遺失／重排」；不能畫成必然遺失。
- TCP 紙帶先經「建立傳送狀態」標記，再以連續、按序的紙帶交付；應用原有表單邊界不能被畫成保留不變。
- UDP／TCP 不使用獎牌、賽道、碼表、速度箭頭或「快／慢」標籤；圖面距離也不代表 latency。

## 元件

### 共用標題與分區

- 圖頂標題：`總機與警衛是兩個工作；UDP／TCP 比較服務語意`
- 上半部標題：`A　轉換／對照與規則判斷分工`
- 下半部標題：`B　兩種運送服務的語意，不比較速度`
- 最底部固定 `比喻邊界` 框，完整列出：
  - `總機的 mapping 不等於警衛放行。`
  - `警衛放行不等於目的 listener 存在。`
  - `外側觀察位址不等於 public IP address、永久身分或可達保證。`
  - `UDP／TCP 只比較 service semantics；實際表現依應用、路徑、負載與實作而異。`

### A：小明、總機、警衛與小華

- 固定角色 `小明` 置左，手持一份不含個資的抽象資料卡；角色旁標 `內側聯絡表示`。
- `總機：轉換／對應` 使用矩形櫃台或交換台圖形，不能使用盾牌、鎖頭或門禁圖示。
- 總機旁放獨立小表格 `暫時對應`：
  - 左欄 `內側聯絡表示`
  - 右欄 `外側觀察位址`
  - 表格下直接寫 `依實作與時間而異；不是永久身分`
- `警衛：依 policy 允許／阻擋` 使用警衛台或雙向閘門圖形，不能畫成改寫聯絡表示的機器。
- 警衛台必須有兩個文字結果：
  - `允許：資料可繼續`，使用有箭頭的實線出口。
  - `阻擋：在 policy boundary 停止`，使用平頭終止線與文字，不只用紅叉。
- 固定角色 `小華` 置右，所在區域標 `外側網路`；小華旁另放 `目的 listener？` 問號卡，明示放行後仍須另確認。
- 外側聯絡表示旁固定警語：`外側觀察位址 ≠ 自動成為 public IP address`。
- NAT／NAPT、mapping、firewall、policy 可作小型正式對照標籤，但生活物件名稱仍須是總機與警衛；不得把兩者合併成 `NAT 防火牆`。

### B：UDP 明信片與 TCP 連續紙帶

- 左側子區 `UDP：一張張明信片`：
  - 至少三張有完整外框、各自編號的明信片，顯示 message/datagram 邊界。
  - 中間可放一個空缺輪廓並標 `可能遺失`；出口次序可用 `①、③、②` 並標 `可能重排`。
  - 固定文字：`保留每份邊界；不保證送達、去重或順序。`
  - 不畫簽收勾、必達終點或應用一定重送。
- 右側子區 `TCP：建立狀態後的連續紙帶`：
  - 起點必有獨立標記 `建立傳送狀態`，之後才是相接的連續紙帶。
  - 紙帶出口以 `可靠、按序的字流` 文字說明；不畫成一張張封包。
  - 送出端可有表單分隔記號，接收端改用不同位置的淡刻度或完全連續帶，旁標 `不保留應用表單邊界`。
  - 固定限制：`可能等待或失敗；不代表立即抵達、應用已處理或具身分安全。`
- 兩子區等寬、並列且沒有競賽終點；中央放 `比較語意，不排名速度` 文字分隔牌。

## 關係、方向與箭頭

- A 區主閱讀方向固定為左至右：小明／內側表示 → 總機／暫時對應 → 警衛／獨立 policy → 允許分支 → 外側網路／小華。
- 總機前後箭頭文字分別為 `內側聯絡表示`、`外側觀察位址`；警衛的箭頭文字只能是 `另做 policy 判斷`、`允許` 或 `阻擋`，不能寫 `轉換`。
- 從 `暫時對應` 到警衛只畫「接著仍須判斷」的閱讀箭頭；不得用打勾或粗直通線暗示 mapping 保證通行。
- 阻擋分支以平頭終止線結束，不連向小華；允許分支連到 `目的 listener？`，再以問號而非成功勾表示仍未證明服務存在。
- A 區箭頭是責任分解與故事閱讀順序，不是固定物理拓撲或真實封包路線；底部必須寫明 NAT/firewall 可能共置或分離。
- B 區 UDP 明信片由左向右，各卡本身保留邊界；TCP 紙帶由左向右連續延伸。A、B 區之間不畫資料箭頭，避免把故事拓撲和 transport 時間線合成一條 wire flow。

## 做到／做不到

| 物件 | 圖中做到 | 圖中做不到 |
|---|---|---|
| 總機 | 轉換／對應內外聯絡表示，留下暫時對照 | 不依 policy 放行、不加密、不驗證身分、不保證可達 |
| 警衛 | 依獨立 policy 允許或阻擋 | 不建立 NAT/NAPT mapping、不把外側位址變成 public、不保證 listener 存在 |
| 外側觀察位址 | 表示特定觀察位置看到的值 | 不自動代表 public/global realm、永久身分或全球可達 |
| UDP 明信片 | 表達 datagram 邊界與可能遺失／重排 | 不表示一定較快、必然遺失、無任何 state 或永不由應用重送 |
| TCP 紙帶 | 表達建立狀態後的 reliable in-order byte stream | 不保留應用 message 邊界、不保證零等待、永不失敗、應用已處理或安全授權 |

生活故事圖：小明的內側聯絡表示先到總機，總機建立暫時對應，再到依 policy 判斷的警衛，最後指向小華所在的外側網路；下方分列保留一張張邊界但可能遺失或重排的 UDP 明信片，與建立狀態後可靠按序交付、但不保留表單邊界的 TCP 連續紙帶；文字明示 mapping 不等於放行、放行不等於 listener 存在，外側觀察位址不等於 public IP address 或永久身分。

## 非顏色辨識方式

- A／B 分區使用字母、完整標題、位置與外框四重區分。
- 總機使用矩形交換台與 `轉換／對應` 文字；警衛使用雙向閘門與 `允許／阻擋` 文字。兩者形狀、動詞和位置都不同。
- 暫時對應使用雙欄表格；policy 使用分支箭頭。Mapping／policy 不能只靠不同底色辨識。
- `允許` 使用尖頭實線箭頭；`阻擋` 使用平頭終止線；兩者都有完整文字，不只用綠色／紅色或勾／叉。
- UDP 使用分離、有外框並編號的卡片；TCP 使用相接長紙帶與建立狀態標記。即使移除顏色也能分辨。
- 外側觀察位址警語置於有標題的註記框，`≠` 與完整文字必須保留，不能只使用警告色。

## 對比要求

- 一般文字與背景對比至少 4.5:1；大型分區標題至少 3:1。
- 箭頭、表格、角色輪廓、總機、閘門、明信片和紙帶外框與背景對比至少 3:1。
- 主要線寬不小於 2 pt；表格與紙帶刻度不小於 1.5 pt；虛線空缺在單欄縮圖下仍可辨識。
- 不在照片、漸層或複雜紋理上放文字；所有標籤使用純色底或充分留白。
- 色彩只能輔助分區；不得承擔總機／警衛、允許／阻擋、UDP／TCP 或 outside/public 的唯一區別。

## 禁止元素與禁止推論

- 不把 NAT 與 firewall 畫成同一框、同一動詞或同一證據；不使用 `NAT firewall`、`NAT 防火牆` 或「有 NAT 就安全」。
- 不把總機畫成路由器、加密器、身份驗證器、ICE/STUN/TURN server 或固定必經設備；不把警衛畫成 address/port 改寫器。
- 不把外側觀察位址標成 public IP，除非圖內同時存在已確認 registry allocation／global uniqueness 的獨立證據；本生活圖預設不提供該證據，因此不得標 public。
- 不用賽道、速度表、火箭、烏龜、獎牌、勝負、長短箭頭或先到終點表示 UDP／TCP 快慢。
- 不把 UDP 畫成保證遺失、完全無 state、必然低延遲或應用永不重送；不把 TCP 畫成保留 message boundary、封包不會遺失、零等待、應用已處理或具機密性／身份保證。
- 不顯示真實 IP、public IP 範例、domain、URL、credential、個資、真實政策規則或可連線目的地。
- 不出現 Chapter 04+ 的 camera/microphone API、PeerConnection、signaling、SDP、ICE、candidate、STUN、TURN、DTLS/SRTP、RTP/RTCP、codec、stats、Node、Wireshark、RTSP、MediaMTX、FFmpeg 或 WHEP。
