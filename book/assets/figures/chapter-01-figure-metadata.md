## r02 表達方式

### 生活故事圖

- A 列保留「準備完整影片 → 影片完成 → 完整影片 → 交付 → 小華觀看 → 小華回應」與小華等待的點線關係。
- B 列改為四個依時間向右排列的事件框；框內以角色姓名、`→`／`←` 與「聲音／畫面」分行標示，清楚表示雙方交錯回應。
- B 列事件之間只用不可見 Mermaid 排版關係，不以一律向右的可見 edge 表示互動方向。
- 「邊產生、邊交換、邊回應」及路徑限制警語置於兩列之後，不參與互動方向。

### 專業圖

- Browser A／B 保持左右等權、相同端點樣式。
- 中央只放上下分離的兩個 label box：`← · · · 協調資訊 · · · →` 與 `← ─── 即時影音 ─── →`。
- 點狀與實線字形、上下位置及完整文字標籤共同區分兩類概念交換；不再使用反向 cycle edge，因此不會以大弧包圍端點。
- Browser 與中央標籤之間只用不可見 Mermaid 排版關係。可見的雙向文字箭頭表達「雙方都需交換」，不主張真實連線或路徑。
- 警語以主圖 subgraph 之後的獨立節點排列，內容縮為兩行，避免成為中央主元件。

## 圖 1-1：完成檔案寄送與持續雙向互動

### Caption

**圖 1-1　完成檔案寄送與持續雙向互動的時間差。**上列必須先準備並交付完整影片，小華之後才能觀看與回應；下列則在內容持續產生時交錯交換與回應。文字箭頭只表示故事中的互動節奏，不表示真實資料路徑。

### Alt text

上下兩條由左向右的時間線比較兩種模式。上列「完整影片寄送」中，小明先準備完整影片，越過「影片完成」界線後才一次交付；小華前段等待，收到、觀看後才回應。下列「持續雙向互動」中，四個事件依時間向右排列，文字箭頭方向交替：小明向小華說明日期、小華向小明追問星期一或星期二、小明向小華修正為星期二、小華向小明指出數字要重算。圖下註明，文字箭頭只表示互相回應的節奏，不代表資料實際路徑。

### 非顏色辨識

- A／B 使用不同列、字母編號與完整標題區分。
- 完成檔案模式使用長方形、雙框完成界線、粗實線交付箭頭與文字；等待使用圓角形狀和點線關係。
- 持續互動的四個事件使用圓角框；框內的 `→`／`←` 方向字元、角色姓名與「聲音／畫面」標籤共同表達交錯方向。
- `時間由左向右` 與限制警語直接寫在圖內，不依賴顏色。

### 對比與灰階檢查方式

- Mermaid source 指定白色內容底、深灰外框、近黑文字與淺灰警語底；固定 renderer 11.16.0 的預覽已確認實際套用這組色值。

## 圖 1-2：WebRTC 通話的最小概念鳥瞰

### Caption

**圖 1-2　WebRTC 通話的最小概念鳥瞰。**Browser A（小明端）與 Browser B（小華端）之間分列協調資訊與即時影音兩種概念交換；中央文字箭頭只區分用途並提醒雙方都需交換，不表示直接傳送、實際拓撲、資料路徑或內部實作。

### Alt text

Browser A（小明端）位於左側，Browser B（小華端）位於右側，兩個端點框大小與樣式相同。中央上列是帶點狀線條字形的「左箭頭、協調資訊、右箭頭」，下列是帶實線字形的「左箭頭、即時影音、右箭頭」。主圖下方另有警語，說明雙向文字箭頭只表示雙方都需交換，不表示直接傳送或實際資料路徑；這是概念鳥瞰，實際拓撲、路徑與內部做法於後章拆解。

### 非顏色辨識

- Browser A／B 由 A／B 字母、中文次標與左右位置識別。
- 協調資訊由上方位置、點狀線條字形、虛線框與完整文字標籤辨識。
- 即時影音由下方位置、實線字形、實線框與完整文字標籤辨識。
- 每個中央標籤都包含明確的 `←` 與 `→`，警語以完整文字限制箭頭語意。

### 對比與灰階檢查方式

- Mermaid source 指定白色端點／標籤底、深灰外框、近黑文字與淺灰警語底；固定 renderer 11.16.0 的預覽已確認實際套用這組色值。
- 依 WCAG 相對亮度公式計算，`#111827` 文字在白底為 17.74:1、在 `#f3f4f6` 警語底為 16.12:1；`#1f2937` 端點框在白底為 14.68:1；`#374151` 虛線框在白底為 10.31:1，均高於規格門檻。
- 產出 100% 灰階測試頁，縮至書頁欄寬，確認 Browser A／B、上下兩列、點狀／實線字形、虛線／實線框、左右箭頭、兩類標籤與下方警語仍清楚。
- 若 renderer 未將 Browser A／B 排為左右等權、中央兩個 label box 排為上下兩層，或警語回到主圖中央，必須再修圖並重新執行 Gate。
